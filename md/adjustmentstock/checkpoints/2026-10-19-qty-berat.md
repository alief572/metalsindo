# Checkpoint 2026-10-19 — Qty dan berat independen

Implementasi rencana pengguna selesai. Tidak ada commit/push, perubahan skema, registrasi menu, export baru, koreksi historis, atau operasi pada database live. Seluruh fixture menggunakan temporary tables InnoDB pada metalsindo_dev.

## Perubahan
- Controller memakai model Adjustment_balance_model untuk validasi, saldo, transaksi dan ledger. AJAX form lama yang merender HTML di controller digantikan endpoint form_options dengan whitelist data.
- PLUS mendukung lot existing/baru; MINUS dan MUTASI mendukung Qty 0, kg eksplisit dan Qty/kg independen. Target mutasi existing harus kompatibel material, lot, bentuk, dimensi dan customer.
- Selisih gross dan operasional dipertahankan; nilai per Qty dihitung ulang. PLUS menjaga total booking kg saat Qty berubah. MINUS/MUTASI menolak booking produksi/delivery. Source kosong dinonaktifkan, bukan dihapus.
- Simpan serial melalui GET_LOCK per database, transaksi dan FOR UPDATE. Semua ledger/snapshot rollback bersama saat gagal. Target baru hanya menyalin metadata asal yang relevan, bukan counter pengiriman/pemakaian.
- Form memiliki preview source/tujuan, kg manual, Qty integer, helper Qty 0, pencarian lot Select2 lokal, serta state loading/error. Save dikunci selama request berjalan; token CSRF diperbarui untuk retry validasi.
- Riwayat menampilkan delta Qty dan total kg; render teks kompatibel DataTables 1.10.7. Izin tombol Add disamakan dengan endpoint. Scoped CSS mengikuti AdminLTE/Geist tanpa animasi dekoratif.

## Verifikasi
- PASS adjustmentstock_balance.php: gross/operasional independen, Qty-only, kg-only, booking, pengosongan dan input invalid.
- PASS adjustmentstock_transactions.php: SQL model sebenarnya terhadap temporary tables berskema identik, PLUS/MINUS/MUTASI, metadata server, saldo gudang, history masuk/keluar, ketepatan Qty/kg, ID invalid, booking, target salah/duplikat, saldo NULL/ganda/kurang, precision, forced rollback dan release lock.
- PASS dua koneksi MySQL: lock adjustment menolak kepemilikan bersamaan dan dapat diambil setelah release. Uji transaksi tidak menjalankan dua HTTP request bersamaan pada data permanen.
- PASS adjustmentstock_controller.php: permission Add/View sebelum akses model/DB, POST-only, JSON kompatibel, error aman dan CSRF renewal.
- PASS adjustmentstock_render.php + parser JavaScript Node: escaping, token CSRF, input constraints, variasi Add permission dan inline JS hasil render.
- PASS adjustmentstock_ui.js + node --check: auto weight, nilai manual/0 dipertahankan, switching mode, preview, kompatibilitas tujuan.
- PASS query options SELECT-only pada data lokal aktual: 1.789 lot dalam 0,148 detik (<3 detik). Regresi transaksi temporary tables sekitar 0,10–0,13 detik.
- PASS PHP lint pada controller/model/views dan skrip PHP baru, git diff --check.
- PASS perhitungan kontras: teks minimal 6,37:1; border minimal 3,64:1 terhadap permukaan yang dipakai. Kontrol dan opsi pencarian lot minimal 44px di scoped CSS.

## Batasan dan TODO
- Tidak dilakukan uji browser, visual runtime atau console browser sesuai arahan pengguna. Render/syntax/state diperiksa lewat CLI; pengujian interaksi DOM aktual tetap belum dilakukan.
- Data lokal mengandung saldo warehouse_stock ganda. Save menolak pasangan material/gudang ambigu, tanpa menjumlahkan atau memperbaiki data lama. Rekonsiliasi perlu task terpisah.
- DOUBLE(40,2) per Qty tidak dapat mewakili semua pembagian. Contoh 100 kg / Qty 3 akan ditolak karena 33,33 × 3 = 99,99. Dukungan semua kombinasi memerlukan perubahan kontrak/precision skema terpisah.
- Lot dengan saldo awal NULL, saldo melebihi kapasitas kolom gudang, atau pengosongan Qty yang masih menyisakan gross/operasional akan ditolak. Tidak menebak atau menormalisasi data lama secara otomatis.
- GET_LOCK melindungi sesama request adjustment. Modul lain tetap bergantung pada row locking/transaksi mereka sendiri.
